## 三、两个根本原因（按发现顺序）

### 根因①：Compose ui 1.8.3 GraphicsLayer 的"录制分发外绘制静默失效"

- `rememberGraphicsLayer` 的层在**录制所在的 draw 分发之外**经 `drawLayer` 绘制会静默不出图（`recreateDisplayListIfNeeded→recordInternal` 异常被吞）；**嵌套 drawLayer**（层 record 块内再画另一 remember 层）恒缺内容。
- 旧构造「玻璃 onDrawBehind 内 recordBlur 取样 contentLayer」两条件全踩 → 模糊层恒为空 → 栏后文字清晰、模糊档位间零像素差。
- **修复（design J）**：悬浮栏全量磨砂的取样与绘制整体移到内容层宿主节点（`glassBackdropContent`）的**同一次 draw 分发**内——内容子树经 `drawContext.canvas` 换靶直接画进模糊层；饱和度拆为独立 saveLayer paint（blur→saturate 顺序与 web 一致）。
- 探针证据：E4–E9 逐项实证（同分发直接绘制可见、跨分发/嵌套恒缺）。

### 根因②：平台 RenderEffect 模糊半径的 ~64 物理像素硬上限

- 模拟器 API 35 半径扫描（20/25/30/40/99dp）：**52px 有效、66px 起整个效果被静默丢弃**（非衰减）——"滑条拖大不更糊/真机死区"的最终解释。
- 修复（`blurRecordScale`）：半径 px 超 `MAX_BLUR_PX=52` 时内容按 `s=52/半径` 缩小录进模糊层、画回时放大 `1/s`——层空间半径恒 ≤ 上限，效果不再被丢弃；全量程有效。
- **已知边界**：RenderEffect 在绘制目标空间应用，缩放不能放大模糊量——**单次模糊视觉封顶 ≈52px**（默认 100dp 起即平台满档平台，100→500dp 的观感差异是"结构熔化"渐进加深）。要突破只能多重模糊叠加（引擎大改，未做）。

## 四、双保险降级体系（低能力设备也不哑）

| 机制 | 内容 |
|---|---|
| `GlassBlurCapabilityProbe` | HardwareRenderer + ImageReader 离屏渲染「高对比源层 → 生产同构模糊层」两帧读回像素、Laplacian 边缘能量比对；后台线程懒触发、进程内缓存；探测期间与失败一律走雾化（不再只看 API 版本） |
| 雾化兜底 `glassFogAlpha` | √ 曲线：`√(半径/满档)×0.92`；默认/满档比例 0.2 恒定 → 默认档钉值 0.4114 跨三次量程变更不漂移 |
| ModelSheet 窗口模糊 | `WindowManager.isCrossWindowBlurEnabled` 检查，系统关跨窗口模糊时显式走 scrim 降级 |
| 文案 | 设置页「玻璃」卡副标题："模糊度：Android 12+ 真实模糊背景，低版本或设备探测失败以雾化近似；磨砂度全版本生效" |

## 五、关键工程事实（后续迭代须知）

1. **DataStore 层夹取是字面量**（data 层不反向依赖 ui 层）：改量程必须同步改 `SettingsRepository.kt` 的 `coerceIn` 与默认值字面量——本次就抓到 `0..60` 残留会把 >60 的滑条值截回。
2. **雾化 √ 曲线的比例不变性**：默认/满档保持 0.2（12/60 = 20/100 = 100/500），默认档钉值 0.4114 不随量程漂移，测试只重钉低半径对比点与越界值。
3. **测试钉值体系**：`GlassFogLegacyTest`（雾化曲线）、`GlassRecordScaleTest`（降采样缩放）、`GlassTransparencyReadabilityTest`（对比度 + 半径 2× 不变式 + withGlassFrost 派生）、`GlassBlurCapabilityProbeTest`（五路径 fail-closed）。改玻璃任何数值先想这四组。
4. **模糊消费方清单**：悬浮顶栏/输入栏（Card 档渐变 + 全量磨砂）、各页玻璃卡片（Frost 档 + 背景磨砂）、模型弹层（窗口级 FLAG_BLUR_BEHIND）。`GlassFill.Card` 只被四处悬浮栏用；`blurRecordScale` 目前只挂悬浮栏路径（卡片路径走 1:1）。
5. **两套模糊机制不可并存**：页内 backdrop 层与窗口级 FLAG_BLUR_BEHIND 有互斥注释约定，动 ModelSheet 时注意。
6. **顺手修复**：L33 果冻按压死参数——`detectTapGestures(onPress)` 消费 DOWN 导致 `GlassSurface(onClick=null)` 时外层 `combinedClickable` 静默失效（历史会话行、CrisisCard 长按中招）。
7. **token 文件**：`docs/design-tokens.json` 的 `component.glassAppearance`（滑条量程/默认）与 `component.glassBackdrop`（引擎默认值）+ 顶层 `meta.note` 是唯一来源声明，三次量程变更均已同步。

## 六、未结案：真机发消息卡死（零 provider 调用）

**现象**：用户真机（小米 HyperOS/Android 12+）发消息永久卡在"正在翻知识库"，API 平台零调用记录。

**排查过程（模拟器 + mock provider 复现法）**：
- 宿主机起 mock provider（`.zcode/mock_provider.py`，记录请求 + 返回规范 SSE/非流式）；
- `adb reverse tcp:8899 tcp:8899` 端口映射（注意：端点策略只放行 https 与 http://localhost，`10.0.2.2` 会被正常拦截报"地址不受支持"）；
- 把模拟器 DeepSeek 指到 `http://localhost:8899/v1` 实测最新包。

**实测结论：App 侧全链路健康，无法复现永久挂起**——
- 路由调用正常（`knowledge_route_empty route_source=llm`）；
- 主请求正常发起；mock 返回不合规流时按设计重试 4 次（~10s）后 `llm_request_failed error=EMPTY_CONTENT`；
- UI 正确转"响应异常"错误卡片（重试/取消）。
- 所有环节有界：路由 10s 双保险（withTimeout + callTimeout）、主请求 connect 15s/read 60s、SSE 层 M10 兜底（干净关流→EMPTY_CONTENT 重试）。

**头号嫌疑（待用户提供信息）**：请求根本没到达服务器 → 设备网络路径（VPN/代理 app、Private DNS、运营商劫持）；或 HyperOS 特有的 Keystore 解密挂起（无法在模拟器复现）。

**待用户执行**：① 应用内「测试连接」自检；② `adb logcat -c && adb logcat -s Wenyan` 抓一轮发送日志（AppLogger tag=`Wenyan`，含 llm_route/llm_request/knowledge_route 全轨迹）。

**模拟器遗留状态**：DeepSeek 提供商指向 `http://localhost:8899/v1`（Key=test-key-123）、MiMo 的 URL 被误改为 `http://10.0.2.2:8899/v1`（无碍，未配置 Key）、mock 服务在后台跑着、测试消息 BLURTEST1-6 在默认会话。

## 七、工作流与协作经验

- **dynamic-workflows 拓扑**（跑了 4 轮）：实现工程师 → 脚本 world.run 测试门禁循环（失败输出回喂）→ 独立评审员（只读找漏洞）→ 复核员 fan-out（逐条 confirmed 才修）→ 双构建门禁 → markdown 报告 artifact。评审抓到过一条 high（探测失败时 31+ 雾化未实现）和一次虚假的"强制雾化回归"声明——**验证声明必须盯生产路径**。
- **会话 Bash `cd` 持久化会带歪工作流 world.run 的 cwd 与 `.zcode` 草稿落点**——门禁一律用绝对路径（`D:\wenyan\app\gradlew.bat -p D:\wenyan\app`）。
- **provider 配额**：start-plan 配额耗尽会停工作流，可 `AmendWorkflow` 换 subagent_model 到个人套餐续跑（缓存导入零重花）。
- **模拟器 M3 Slider 盲点坐标随滚动漂移**：先 `uiautomator dump` 拿 SeekBar bounds 再 tap，别凭记忆坐标盲点（曾误把色相拨到 70）。
- **验收截图判定别只信单一指标**：lapvar/RMS 会被栏上清晰元素主导失真，裁剪放大目检 + 像素差双管齐下。
